## 要实现的用户路径

拿到一台受支持的 Ubuntu VPS → 粘贴一条安装命令 → 得到面板地址和初始账号 → 网页安装游戏 → 选择最小组件或全套 → 设置服名、进服密码、人数 → 确认运行状态 → 复制加入说明给朋友。

正常路径不要求装 Node、编译插件、编辑 JSON/CFG 或 rsync。云安全组仍需用户在云控制台放行；面板必须给出具体 TCP/UDP 端口和操作说明。异常时允许使用面板显示的一条修复命令，不能把复杂 SSH 排障当作向导完成。

## 三个里程碑与交付顺序

| 阶段 | 可交付内容 | 通过条件 |
|---|---|---|
| P0：统一契约 | 插件目录/清单、配置字段、向导状态、测试环境和依赖锁定规则 | 发布工具与运行时消费同一真实载荷；明确版本/许可和兼容验证责任 |
| M1：一条命令装面板 | CI Release、get.sh、专用用户、HTTPS/systemd、网页配置与自动重启、未装游戏空状态 | 干净 Ubuntu 首装成功；重复执行保留数据；改端口后仍可登录；失败可恢复 |
| M2：插件包 | Metamod/SourceMod、自带插件、可选多人/特感/积分包、后续补装 | 最小和全套两条路径均通过；保留用户配置；重启后实际识别加载能力 |
| M3：基础设置与加入 | 中文服名、进服密码、地区、多人数量控制、朋友加入指南 | 保存/运行值分开显示；换图和重启保持；可选多人组合通过超过 4 人入服 |
| E：整体交付 | 把 M2/M3 接入首次向导，完成浏览器、实机、升级回归 | 从空机器到朋友入服闭环通过后，才能宣传“一键部署并游玩” |

实施不是简单等待 M1 全部结束再写 M2/M3：P0 先固定契约；M1 的发布/配置底座先行；M2 与 M3 后端完成后再接完整向导。M1 中期可单独测试“面板可访问”，不能据此宣布完整新手流程交付。

## 最小和全套的实际含义

- **最小默认**：Metamod、SourceMod、白名单、`sipreset` 以及本次新增的中文服名插件。默认不增加第三方多人玩法；`sipreset` 没有 Infected Bots 时显示“需要特感扩展包”，不能伪装成可用。
- **可选多人包**：l4dtoolz + 经验证的生还者管理插件及依赖，提供真实可写的人数设置。初版认证目标为 4–12 名合作玩家；内部客户端槽位、玩家上限、生还者数量分别管理。
- **可选特感包**：Infected Bots、匹配版本的依赖及 auto/te8/te12/te16 数据，保留已有数据文件。
- **可选积分包**：固定来源的 Points System 和必需依赖。来源、源码、许可或兼容性不明时阻断该包发布，不能拿一个空的“全套”按钮作为完成。

人数不是单独写 `sv_setmax` 就完成：该变量管理客户端容量；多人角色生成由其他插件负责。此处设计依据 [l4dtoolz 上游说明](https://github.com/lakwsh/l4dtoolz/blob/main/README_EN.md)和 [MultiSlots 上游说明](https://raw.githubusercontent.com/fbef0102/L4D1_2-Plugins/master/l4dmultislots/readme.md)。具体版本与依赖闭包在 P0 固定，真实入服是最终验收。

## 本次已处理的设计问题

1. **目录统一**：只使用 `panel/packs/manifest.json` 和 `panel/packs/payloads/`，发布测试直接消费最终 tarball，避免两套目录各自通过测试。
2. **向导可续接**：向导完成状态独立于“已有 owner”；首次初始化写入明确的未完成标记，重启不会跳过剩余步骤。
3. **配置写对文件**：把 `--config` / `L4D2PANEL_CONFIG` 的实际路径传到上下文，禁止猜测 `base/panel.json`。
4. **重启不误判**：同端口不绑定探测自己的监听；变端口检查只能预检，最终看新进程与新配置是否启动。没有 systemd 管理能力时禁用自动退出。
5. **失败能恢复**：备份、待确认配置记录、限次启动回退和单命令恢复；旧安装、端口冲突、下载失败不能打印成功。
6. **插件能力真实**：文件存在、框架加载、依赖完整、功能可用分别记录；启动/重启后刷新能力，查询失败显示未知。
7. **中文与人数有验收**：中文放 SourceMod data 文件，游戏 CFG 保持 ASCII；人数区分容量与生还者配额，超过 4 人实测。
8. **朋友真的能加入**：提供开控制台、设置密码、connect、客户端地图依赖及防火墙说明；本机查询成功不代表公网可达。

两份原评审结论已纳入上述 OpenSpec 设计和需求；原始规划核对报告保留在维护者工作区。
